# 最近 7 天性能与故障审计（2026-08-13）

## 范围与口径

- 数据源：生产环境 `ChildPerformanceMetric`、`star-monsters-api.service` systemd 日志。
- 时间范围：审计时刻向前 7 天。
- 原始样本：6,880 条，其中页面打开 1,923 条、API 1,873 条、运行错误 5 条。
- 真实页面打开口径会排除未登录探测、离线/隐藏页中断、已完成任务的预期 409、旧版绝对时间计时和跨越浏览器挂起的计时器。

## 结论

1. 页面正常打开并没有整体恶化。排除 iPad/Safari 挂起产生的假慢样本后，平均打开约 232 ms，P95 约 497 ms，超过 1 秒 15 次。
2. API 成功请求的服务端耗时普遍为几十毫秒。任务列表成功请求服务端平均约 56 ms，星宠、足迹、航图等读取平均约 15–40 ms。
3. 过去 7 天 API 服务启动 252 次。频繁部署/重启与同一秒多个接口同时出现 `status=0` 或 `502` 高度一致，是主要可用性问题。
4. API 原始失败共 319 次：`status=0` 288 次、`502` 21 次、`400` 7 次、`409` 2 次、`404` 1 次。至少 127 次 `status=0` 集中在 32 个“同秒多接口失败”时间点，符合服务短暂不可用或连接中断特征。
5. 5 次 React 渲染失败的旧记录没有错误名称、消息和发布版本，无法从历史数据反推具体组件。新版本已补齐错误上下文，后续可直接定位。
6. 8 月 9 日 `MathPracticeSettings` 表缺失错误属于已修复历史故障；8 月 10 日之后没有再次出现。
7. 一次 DeepSeek 周报返回格式错误属于供应商输出异常，已有结构校验和修复重试；一次系统 AI 配置空密文导致 500，已增加配置完整性校验并修复无新密钥保存时的空值路径。

## 本次修复

### 红包交互

- 将 Safari 容易出现命中测试异常的负层级动画改为明确的正层级。
- 动画、图片、光环不再拦截指针；拆红包和关闭按钮显式启用触控命中。
- 拆红包请求增加 12 秒超时，避免网络异常时永久停在“打开中”。
- 红包操作纳入性能诊断的关键交互。

### API 稳定性

- GET 请求遇到网络异常或 `502/503/504` 时短暂等待后自动重试一次。
- POST/PUT 等写请求不自动重试，继续依赖原有幂等键，避免重复业务操作。
- 纯前端发布在 API 构建、Prisma 和依赖未变化时不再重启 API，减少短暂 502 窗口。
- API 确需重启时，发布脚本等待健康检查成功才结束。

### 诊断准确性

- 页面进入后台时清除未完成导航计时，避免 Safari 恢复后产生几十秒或几分钟的假打开时长。
- 离线/隐藏页中断、预期任务状态冲突和浏览器挂起计时从故障统计中排除，但原始数据仍保留。
- 新增错误名称、错误消息、前端发布版本字段；敏感查询参数在上报前脱敏。
- 超级后台“最近真实慢等待与失败”增加错误详情和版本列。
- 性能查询移除每条指标对孩子和家庭的嵌套关联查询，改用一次性映射，降低诊断接口开销。

### AI 与后台错误

- DeepSeek/MiniMax 密钥缺字段时返回明确 409，不再触发解密 500。
- 修复系统 AI 和 MiniMax 配置在未更换密钥时，upsert `create` 分支访问空加密对象的问题。
- 主动来信话术部分生成成功时返回已保存进度，不再把可继续补齐的部分成功误报为 502。

## 发布后观察指标

- API 服务启动次数：除 API 代码、Prisma 或依赖变更外，前端发布应不再增加。
- `status=0/502`：关注是否仍出现同秒多接口成片失败。
- 页面打开 P95：使用新口径，目标持续低于 1 秒。
- 运行错误：新记录应包含 `errorMessage` 和 `appVersion`，发现后按版本和路由定位。
- 红包操作：关注 `open_pet_red_packet` 的失败数与 P95。
