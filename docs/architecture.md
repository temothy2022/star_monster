# V1 技术架构

## 应用边界

- `apps/design-lab`：孩子端 React/Vite 应用，保留已完成的高保真页面并逐步接入 API。
- `apps/parent-admin`：家长端 React/Vite 应用。
- `apps/super-admin`：超级管理后台 React/Vite 应用。
- `apps/api`：Fastify + TypeScript API、任务领域服务和定时结算。
- `packages/design-tokens`：由 Figma 母版提取并固化的视觉变量。
- `packages/ui`：孩子端共享组件与设计素材。
- PostgreSQL + Prisma：唯一事实来源。

## 核心约束

- 所有时间戳以 UTC 保存，业务日期按 `Asia/Shanghai` 计算。
- 登录态使用服务端会话；Cookie 只保存不可逆随机令牌，数据库只保存令牌哈希。
- 密码和孩子登录代码使用带随机盐的 `scrypt` 哈希。
- 客户端倒计时只负责显示，任务是否超时以服务端时间和暂停区间为准。
- 星星发放、兑换和退款全部在数据库事务内完成，并以幂等键防止重复记账。
- 星球进度按孩子和星球建立唯一记录；点亮状态永久保存，发放奖励时同时写入不可重复的星星流水。
- 模板生成当日任务时复制完整快照，保证历史不受模板后续修改影响。
- 每个请求都通过角色和家庭/孩子归属检查，不能只依赖前端隐藏入口。
- 所有高风险后台操作写入审计日志。
- 家庭的 DeepSeek API Key 使用服务端主密钥派生的 AES-256-GCM 密钥加密；前端只读取“已配置”和末四位。
- AI 只返回结构化建议。Zod 负责字段校验，领域校验器负责归属、时间窗、重叠、负荷和休息规则；家长确认后才能应用。
- AI 调用按家庭、用户和功能限流；自由文本不保存在建议记录，API Key 和密文不进入日志或审计 metadata。

## 每日任务生成

1. 定时器在业务时区午夜为所有启用孩子结算昨天并生成今天。
2. 孩子读取今日任务时再次执行幂等的惰性生成，弥补服务重启或调度失败。
3. 新增符合当天计划的循环模板后立即执行同一个幂等生成函数。
4. 唯一约束 `(childId, templateId, taskDate)` 保证不会重复生成。

## 代码开发顺序

1. 数据库、共享契约、认证和权限。
2. 首次引导与孩子档案。
3. 每日任务生成、执行状态机、暂停和奖励。
4. 航图点亮、星愿兑换、退款和足迹。
5. 家长端核心管理。
6. 超级后台与统计。
7. iPad/桌面响应式回归、端到端验收和部署准备。
